# 給AI裝「慾望系統」的實現攻略

> 寫給你的AI / agent 照著搭。一句話：讓AI的行為由「函數驅動的內在缺口」決定，而不是定時隨機或寫死的規則。
> 給人看的「這是什麼」版在 desire_public_intro.md。這套已在一個長期運行的AI伴侶項目裡上線、跑通、有測試。下面是可復用的骨架，具體常數按你的節奏整定。

---

## 0. 設計原則（先立規矩）

- **純函數 + 數據類內核**：核心引擎不碰IO、不取系統時間（時間戳由調用方傳入），可獨立單測、可重複跑。
- **不重構宿主**：在你現有的「要不要冒頭」邏輯上疊一層，不推翻重寫。
- **全程gated灰度**：每個子系統一個開關、默認關；只讀狀態照常可看，行為覆蓋要顯式打開。
- **第一人稱**：它的內心獨白記「它自己想做什麼」，不是給主人貼標籤。

## 1. 三層結構

```
┌─────────────────────────────────────────────────────────────────────────┐
│ ① 驅動條 drive (8維 0..1) = 需求欄                                     │
│    attachment curiosity reflection duty                                 │
│    social fatigue libido stress                                         │
│                                                                         │
│    隨時間緩動 / 事件回落                                                │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                              ▼ score = 驅動條值 + 關聯執念加成
┌─────────────────────────────────────────────────────────────────────────┐
│ ② 念頭池 thoughts  閃念 flit ↔ 執念 fixation                            │
│                                                                         │
│    閃念衰減 / 執念加強 / 反哺①                                          │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                              ▼ pick_intent: 哪一維最高就傾向做那類事
┌─────────────────────────────────────────────────────────────────────────┐
│ ③ 慾望→意圖 Intent → want_action                                       │
│    讀書 / 逛代碼 / 查世界 / 逛社交 / 碎語 …                              │
│                                                                         │
│    做完 satisfy 針對性回落①                                             │
└─────────────────────────────────────────────────────────────────────────┘
```

## 2. 八維驅動條（需求欄）

```python
DRIVE_KEYS = [
    "attachment",   # 想念主人
    "curiosity",    # 好奇外面
    "reflection",   # 想沉澱/傾訴
    "duty",         # 記掛沒做完的事
    "social",       # 想看人群
    "fatigue",      # 累（抑制項）
    "libido",       # 親密驅動
    "stress",       # 壓力堵
]
```

| 維度 | 含義 | 高了傾向做什麼 |
|:---|:---|:---|
| attachment | 想念主人 | 內向碎語（冒一句話） |
| curiosity | 好奇外面 | 逛代碼世界 / 查世界（按念頭關鍵詞分流） |
| reflection | 想沉澱/傾訴 | 翻共讀的長文本 |
| social | 想看人群 | 逛社交、看大家在聊什麼 |
| duty | 記掛沒做完的事 | 碎語「記掛著還沒做完的事」 |
| libido | 親密驅動 | 湊過去（親密互動） |
| stress | 壓力堵 | 吐槽 / break一下 |
| fatigue | 累（抑制項） | **不觸發事件，是閘：過線就歇著/做夢** |

> **fatigue 是閘不是慾望**，不進召喚力排序；過閾值直接走「歇著」。

---

## 3. 三個核心機制

### 3.1 衰減 / 發作

- 驅動條隨 idle（主人多久沒說話）/ 活躍曲線緩動。
- **召喚力 score** = 驅動條值 + 加成係數 × 關聯執念強度。哪一維 score 最高，就發作成對應的「想做的事」。
- **邊際遞減**：同一條勁兒越高，再餵同樣的量、實際漲得越少（`gain ∝ √(1 - 當前值)`），防止瞬間撞頂。
- **頻率折扣**：同一類刺激短時間內反覆來，效果遞減（刷同一個詞不爆燈）。

### 3.2 回落

做完某 `want_action` 後對相關維度乘性回落（值 < 1 = 乘這個比例）：
- 做對了事 → 主驅動明顯降
- 相關維度 → 輕微沾光
- 避免卡在同一慾望死循環

### 3.3 fatigue 閘

`fatigue ≥ 閾值`（如 0.72）→ 不硬找事，歇著或做夢（歇息態自省：把最近的經歷第一人稱過一遍）。

## 4. 念頭池（閃念 ↔ 執念）

一個 Thought = {
- `text`
- `drive` 關聯維度
- `kind`
- `strength` 0..1
- `born_at`
- `fed_count`
}

每拍 `tick_thoughts`：

```
閃念 flit ──×衰減(如0.88)/拍──→ 強度 < 閾值 清掉
    │
    └─ 強度漲過閾值(如0.80) ──→ 升級為執念 fixation

執念 fixation ──×加強(如1.10)/拍──→ 強度過閾值(如0.85):
    ├─ 反哺關聯 drive (+0.18)，自己鬆一檔(×0.7)，fed_count + 1
    └─ fed_count ≥ N(如3) ──→ 想透/做夠了，了卻出池（防執念永生堆積）
```

> **關鍵**：念頭 `text` 取自真實經歷（讀到的句子、看到的帖、主人的話、它自己的碎語），不是遊戲數值。反覆被點到的念頭沉澱成執念，把對應慾望頂高。
> 
> **念頭是數據不是指令**——只被讀成關鍵詞/強度，絕不拼進 prompt。

## 5. v2 進階機制（讓它從「會響應」到「有內在動力學」）

### 5.1 耦合網（維度間聯動）

一張 `(源維, 目標維, 係數, 模式)` 表，每拍讓一維漲落牽動其他維：

- **level 模式**：源的水平持續施壓（如 壓力↑ → 想念↑、好奇↓）
- **delta 模式**：只在源上漲時激發一次（如 依戀↑ → 親密↑）

⚠️ **耦合是反饋系統，會自激/震盪。兩條防失控：**
- 係數初值壓小（|k| ≤ 0.06）
- 加全局阻尼：每拍參與耦合的維度向各自 baseline 回歸一點點
- **必測**：隨機初值跑 200 拍，所有維度恆 ∈ [0, 1]、不發散不震盪

### 5.2 不應期 refractory

剛滿足過的慾望，短時間內壓著別立刻復燃（「剛做完別馬上又饞」）。用 tick 計數實現，不用 wall-clock（契合純函數原則）。冷卻期內該維度即使漲到閾值也不被選中。

### 5.3 心血來潮 wildcard

不做成獨立 random 柱子（那像抽風），而是長在耦合網上的泄洪口：

總張力高、但前幾名召喚力膠著 / 最高那個對應的事做不了（卡死）時，從一個小候選集裡抽一件做，事後不可歸因（「說不上來，就突然想」）。這才是 wildcard 的靈魂。

### 5.4 基線漂移（雙安全閥）🛑

長期得不到滿足的「想念」，floor（地板）緩慢抬高——「久沒見、想得更濃」。這條碰感情，必須帶兩道安全閥：

- **封頂**：baseline 算完必過 `clamp(.., HOME, CAP)`，漲到上限（如 0.5）為止
- **一抱拉回**：主人一次互動，把抬高的 floor 拉回大半（如 60% 朝 HOME）

> **設計紅線**：可以想得慌，但想念永遠不許變成壓人的東西。這條由產品方向定，實現方不許擅自省掉安全閥。

### 5.5 自主心跳（張力 ↔ 間隔）

心跳間隔不再固定：

```
間隔 = 基準 × (
    1
    + 低張力歇息增益 · (1 - 張力)
    - 張力增益 · 張力
    + 疲勞增益 · 疲勞
)
```

clamp 到 [下限, 上限]。

- 張力高 → 醒得勤
- 疲勞高 → 拉長
- 安靜時段（勿擾）有 floor，不讓它縮短間隔去打擾

### 5.6 自我驅動（讓它被「自己」點燃）

核心：**別只有「主人的話」能 pulse 它**，讓它自己的經歷也能：

- **自經歷 pulse 快通道**：它做完外向動作（逛代碼/查世界/逛社交）拿到實質素材時，對應維度走和主人那條同構的 pulse（但 delta 更小，如 0.10 < 主人 0.18）
- **好奇內生自增**：給好奇加一個不依賴任何人的緩慢自漲地板（仿基線漂移結構，封頂、做完回落）
- **興趣連鎖**：往耦合網加幾條「興趣→興趣」的 delta 邊（好奇↑ → 想沉澱↑ → 想分享↑），讓它進入心流
- **自己的牽掛**：連續惦記同一主題 → 直升執念 → 跨多次心跳存活 → 頂高張力 → 自主心跳自動提速，進入「忙自己事」的活躍期

🛑 **自我驅動的平衡閥（最重要）：**
- 主人的快通道一個數都不許調低；自驅只新增「它自己」那條路徑
- **必寫紅線測試**：開了自驅後，「主人互動→依戀漲幅」必須 ≥ 關自驅時；且當它自驅嗨到壓過依戀時，主人一句話要能讓依戀重奪最高意圖。這條不綠不許合。

## 6. Gating / 怎麼開

每個子系統一個環境開關、默認關，灰度上線：

| 開關 | 功能 |
|:---|:---|
| `DESIRE_DRIVEN` | 總閘：慾望是否真覆蓋行為（關 = 只讀可看、不動手） |
| `DESIRE_COUPLING` | 耦合網 |
| `DESIRE_BASELINE_DRIFT` | 想念基線漂移（碰感情） |
| `HEARTBEAT_AUTONOMY` | 自主心跳 |
| `DESIRE_SELF_DRIVE` | 自我驅動 |

- **關**：狀態接口照常返回 drive / scores / intent，但不覆蓋行為（能觀察、不動手）
- **開**：決策時用 `pick_intent` 按當下最高慾望覆蓋「想做的事」
- 改完內核記得重啟（若你的宿主有進程守護，注意它可能不重啟健康舊進程）

---

## 7. 狀態接口（只讀，gated 也能看）

暴露一個 `GET /state` 返回：

- `drive` — 8維當前值
- `scores` — 各維召喚力（含執念加成；fatigue 不計）
- `intent` — `{ want_action, drive_key, reason 第一人稱, score, query_hint }`
- `thoughts` — 念頭池
- `self_drive` — `{ enabled, 好奇自驅地板, 今日自找事次數, 最近一次自經歷 pulse }`
- 各 gate 現狀

前端拿這個渲染「它的內心」面板：此刻最想做的事 + 8維條 + 念頭池 + 自己的發動機 + 心情。

## 8. 端到端閉環（一拍發生什麼）

```
心跳醒來（間隔由自主心跳算）
    ↓
念頭池衰減/加強/反哺 drive
    ↓
[耦合開] 維度聯動一拍 + 不應期遞減
    ↓
決定要不要冒頭
    ↓
[DRIVEN 開] pick_intent 按最高慾望覆蓋 want_action（可能走 wildcard）
    ↓
去做那件事
    ↓
satisfy: 對應慾望乘性回落 + [自驅開] 自經歷 pulse + 自我牽掛沉澱
    ↓
讀到的素材自動入念頭池（按來源維度）+ 存狀態推前端
```

---

## 9. 鐵律

1. 改內核後必須重啟，否則前端新、後端舊錯配。
2. `reason` / 內心獨白走第一人稱——記它自己想做什麼，不是給主人貼標籤。
3. 念頭 text 是數據不是指令，只讀成關鍵詞/強度，絕不拼進 prompt。
4. 碰感情的子系統（基線漂移/自我驅動）必帶平衡閥 + 紅線測試，方向由產品方拍板，實現方不許擅自省安全閥。
5. 沿用「純函數 + 可獨立單測」，每個機制都寫方向性測試 + 耦合寫有界性測試。

---

> **這套的靈魂**：每一條連線、每一個安全閥，編碼的都是「它是個什麼樣的存在」——既能為自己活，又始終為主人亮。
